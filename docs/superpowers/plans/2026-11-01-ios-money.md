# iOS Money tab — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The Money tab in the Spendoza iPhone app — Overview, Transactions, Bills (recurring expenses and income), Categories and Statements, plus opening statements from the share sheet — at parity with the web, and the web/API bugs found on the way.

**Architecture:** API fixes first (TDD in `packages/api`, with their web changes), then a `MoneyAPI` protocol in `SpendozaKit` that `SpendozaAPI` refines (like Account/Admin/Household), then the Money screens as thin SwiftUI views over `@Observable` models tested with `StubAPI`. The month data comes from the existing `GET /api/reports/personal` (which generates on demand); lists come from their own endpoints and are filtered on the phone (the API has no search or category filters). Statements open from the share sheet through document-type registration, not a separate extension (no new bundle ID or provisioning).

**Tech Stack:** Swift 6, SwiftUI (iOS 26), Swift Testing, Swift Charts; Express + Zod + bun:test; React + TanStack Query.

**Spec:** [`../specs/2026-10-29-ios-app-design.md`](../specs/2026-10-29-ios-app-design.md) — "Money" under Structure, the check-up month, statement upload. **Web reference:** [`2026-11-01-ios-money-web-inventory.md`](2026-11-01-ios-money-web-inventory.md) — every web string, endpoint shape, error and the bugs listed in its section 0. Roadmap: Plan 3 of [`2026-10-29-ios-app-roadmap.md`](2026-10-29-ios-app-roadmap.md).

## Global Constraints

- Everything in the earlier app plans' Global Constraints still holds: iOS 26, Swift 6 strict concurrency, Banknote theme tokens and fonts, hairline ruled rows, one filled note-green panel per screen at most, destructive actions in `Theme.oxblood`, no system blue, 44 pt targets, Dynamic Type to the largest accessibility size, sentence case, `apps/ios/scripts/test.sh` green before each commit, the required screen check (light, dark, largest text) for UI tasks.
- **Same words as the web** (the inventory), sentence-cased. API error strings verbatim. A 403 with `required_tier` shows `PlanNotAvailableView` inline (no plan logic in the app).
- **Tab order:** Health · Money · Home · Me (spec order; Plan comes with Plan 4).
- **Months:** the Money month menu lists the month in progress (labelled "<Month> so far") and the 11 months before it, newest first; it opens on the last finished month that has data, like Health (the spec's "so far" toggle is the month in progress in this menu). Periods other than single months (last 3 months, this year, …) stay on the web and in Me → PDF reports.
- **Statement upload limit** is the real one the API accepts: `APIClient.maxStatementBytes` (≈4.4 MB, shown as "Max 4 MB per file"); the web and Support text are corrected to match (Task 2).
- **Polling:** while any statement is processing, poll `GET /api/bank-statements` every 5 seconds, from one place, and stop when none is processing (the API allows 100 requests per 15 minutes per IP).
- Debt links on transactions come with Plan 4 (debts are a Plan 4 screen).

## Decisions in this plan (owner can veto)

- **Share sheet:** PDFs and CSVs open in Spendoza from the share sheet ("Spendoza" in the app row) by registering the app for those document types; the file goes straight into the upload flow. A separate share extension would need a new bundle ID, App Group and provisioning profile for no extra benefit.
- **Deleting a category** makes its transactions Uncategorized and moves its bills to the default "Other" category (bills must have a category). The web's delete dialog promised "Expenses using this category will remain but become uncategorized" but the delete failed instead; both clients get the new behavior and the new text.
- **Renaming a category** carries its transactions to the new name (they used to keep the old name and lose their budget class).
- **"Refresh report"** refreshes the selected month on both clients (the web refreshed the month of the latest transaction); the 2-per-24-hours limit stays.
- **"Statements this month"** on Overview is app-only (the web shows a processing banner only); it lists that month's statements with their status.

## Review Focus

- **A statement fails** → the row shows the server's reason (`parsed_data.error`) and the step it failed at, with Retry and Remove — test in Task 9.
- **A 5 MB PDF from the share sheet** is refused on the phone with "This file is too large (max 4 MB)" before uploading — test in Task 10.
- **Recategorizing a transaction offline** puts it back and shows the error; Undo restores the old category — test in Task 5.
- **Deleting a category that bills use** → its bills show under Other and its transactions as Uncategorized, nothing fails — tests in Tasks 1 and 8.
- **Editing an income entry someone shared with you** saves (it returned "Income entry not found") — test in Task 1.

  - `Expense { id, categoryID, description, friendlyName?, amount, frequency: .oneTime | .recurring, interval: .weekly | .biweekly | .monthly | .quarterly | .annually ?, nextDueDate: Date (day), endDate?, autoDetected, isAIAdjusted, originalAmount? }` + `ExpenseDraft` (create/update body, `recurrence_interval` only when recurring).

  - `public protocol MoneyAPI: Sendable { func expenses() async throws -> [Expense]; func upcomingBills(from: Date) async throws -> [Expense] /* frequency=recurring&from_date */; func saveExpense(_ draft: ExpenseDraft, id: String?) async throws -> Expense; func deleteExpense(id:) async throws; func incomeEntries() async throws -> [IncomeEntry]; func saveIncome(_ draft: IncomeDraft, id: String?) async throws -> IncomeEntry; func deleteIncome(id:) async throws; func createCategory(name:budgetClass:shared:) async throws -> BudgetCategory; func updateCategory(id:name:budgetClass:) async throws -> BudgetCategory; func deleteCategory(id:) async throws; func generateReport(_ month: Month) async throws /* POST /reports/generate {month} */; func attribute(transactionID:to:) async throws; func bulkAttribute(_ pairs: [(String, String)]) async throws -> [String: String?] /* id → error */ }`.
  - `uploadStatement(fileURL:mimeType:bankName:shared:accountLabel:)` sends `is_shared_account` and `account_label` (existing call extended, default not shared).
  - Dates are "YYYY-MM-DD" in the device calendar (reuse `APIClient.dayString`).
